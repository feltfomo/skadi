# skadi

my nixos configuration for khion and lumi, plus an installer and disposable test targets.
[den](https://github.com/denful/den) composes the hosts and users.
home manager configures user programs.
[lexicon](https://github.com/feltfomo/lexicon) declares programs and managed files, and provides praxis.

## everyday commands

```fish
praxis rebuild khion
praxis rebuild lumi
praxis check
praxis update input lexicon
praxis flake update
```

`praxis rebuild <host>` regenerates `flake.nix`, formats the repository, runs the full check, then asks before switching. it uses den's `nh` wrapper for the selected host. choose the machine you are running on. it does not deploy over ssh. a lock prevents overlapping rebuilds.

all commands use the live `/etc/skadi` checkout, regardless of your current directory. `praxis.nix` declares them, and `modules/flake/praxis.nix` exposes the package and app. feltfomo's home manager profile and the development shell include the dispatcher and shell completions.

| command | action |
| --- | --- |
| `praxis gen` | regenerate `flake.nix` from module declarations |
| `praxis fmt` | run the repository formatters |
| `praxis check` | run `nix flake check -L`, including both real host builds |
| `praxis update input <input>` | update one declared flake input |
| `praxis flake update` | update every flake input |
| `praxis rebuild <host>` | generate, format, check, then switch khion or lumi |

put praxis options before the command. extra rebuild arguments go to the final switch only. a dry switch still runs generation, formatting, and checks.

```fish
praxis list
praxis help rebuild
praxis --plain plan rebuild khion
praxis rebuild khion -- --dry
```

`flake.nix` is generated by flake-file. edit input declarations beside their owning modules, or change output wiring in `outputs.nix`, then run `praxis gen`. do not edit the generated manifest.

### before praxis is installed

```fish
nix develop /etc/skadi
# or run the dispatcher directly
nix run /etc/skadi#praxis -- rebuild khion
```

activation installs the dispatcher for feltfomo. an installed dispatcher keeps the command declarations from its build. use `nix run /etc/skadi#praxis` or enter a fresh development shell to try declaration edits before activation.

## machines

| host | configuration |
| --- | --- |
| `khion` | nvidia desktop, wayland, gaming, impermanence, feltfomo |
| `lumi` | gnome laptop, feltfomo and a restricted family account |
| `vm` | disposable qemu target for installation and first-boot tests |
| `generic` | discovers hardware and disk during installation, starts with an `owner` account |

khion restores a blank root snapshot at boot. declare persistent system and user state before relying on it. provision sops secrets before rebuilding a new account or machine, and test login from a fresh tty before switching the boot generation.

## installation and recovery

build the installer:

```fish
nix build .#nixosConfigurations.installer.config.system.build.isoImage
```

flash `result/iso/*.iso` in raw mode. from the iso, `skadi-install <host>` partitions the target disk and installs the selected host. with no host on a tty, it opens the host and aspect picker. `--drop` omits selected top-level aspects for that install without changing the committed host.

never run disko or `skadi-install` against a running host. they can repartition disks.

run the disposable installation test:

```fish
nix run .#vm-test -- --host vm
```

it builds the iso, installs onto an encrypted vm disk, removes the iso and checks the installed system. artifacts live under `~/.cache/skadi-vm`.

den's wrappers also work without praxis:

```fish
nix run .#khion
nix run .#khion -- switch
nix run .#khion -- switch --dry
```

with no action, the wrapper builds the host. `switch` activates through `nh os`. replace `khion` with the intended real host.

compare closures before switching:

```fish
nix build .#nixosConfigurations.khion.config.system.build.toplevel
nix store diff-closures /run/current-system ./result
```

`sudo nixos-rebuild switch --flake /etc/skadi#khion` is a recovery fallback.

## remote tools

khion runs desktop commander behind mcp-proxy and an authenticated tailscale funnel gateway. the gateway exposes `/mcp`. pi connects to the hosted context7 and github endpoints directly. exa comes from pi web access.

`configs/pi/mcp-adapter.json` declares the servers. `modules/aspects/pi.nix` links it to `.pi/agent/mcp-adapter.json` through furnish. the pi wrapper enables exclusive mode to disable other config discovery and codex imports.

the header helper reads `/run/secrets/desktop-commander-mcp-token` on khion. other hosts need `DESKTOP_COMMANDER_MCP_TOKEN` from a private secret source. github needs a personal access token in the adapter's credential store. after activation, use the masked prompt:

```fish
pi-mcp-adapter token set github
```

the gateway removes its credential before forwarding to desktop commander and redacts it from access logs. context7 and github receive no gateway credentials. tokens stay out of the managed json and nix store. privileged activation and secret provisioning remain manual operations.
