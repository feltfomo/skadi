# Errors and outcomes

## Author-shape errors

The surface rejects:

- non-list or non-string set claims;
- non-function `when`;
- both polarities on one axis;
- non-string `label` or `source`;
- `value` mixed with inline config;
- a scope using a descriptor's forbidden author key;
- unknown merge profiles through profiled doors.

## Impossible diagnostics

Leaf stages report:

- ambiguous bare aliases;
- a claim materializing to no member because of an unknown name or disjoint nest;
- a relation with no compatible modeled pair.

These run before selection. An impossible declaration fails every build, not only a matching one.

## Missing context

A narrowed set axis needs its `ctxKey` entity. Global claims don't. Strict doors separately validate the supplied context tuple even when no authored claim would read it.

## Inactive

A satisfiable claim that doesn't match the current context is inactive. This isn't an error and its payload isn't merged.

## Merge failures

- strict scalar conflict: co-owners set different values;
- single-writer violation: a foreign contributor touches a locked path, even with an equal value;
- unknown list strategy;
- unknown profile or profile disagreement;
- invalid profile attrset treatment.

Conflict and lock diagnostics render path and safe contributor identity, never arbitrary values.

## Stage errors

A malformed or unknown stage view throws rather than silently disabling an invariant. Tree and survivor diagnostics follow the same structured renderer as leaf diagnostics.
